# J.S. Handloom

A static website for J.S. Handloom — authentic Bengal handloom sarees, WhatsApp-led commerce, retail and wholesale.

Live site: [https://swapnadeep2k.github.io/J.S.HANDLOOM/](https://swapnadeep2k.github.io/J.S.HANDLOOM/)

## About

J.S. Handloom is a traditional handloom brand from Bengal offering handwoven sarees across categories including Muslin, Matka Silk, Murshidabad Silk, and Cotton. The site is a plain HTML/CSS/JS static site with a Node build script — no framework, no npm dependencies at runtime. Commerce is handled entirely via WhatsApp enquiry (no accounts, no payment gateway).

## Pages

| Page | File | Purpose |
|---|---|---|
| Home | `index.html` | Hero, trust strip, collections, video, brand story, testimonials, featured products |
| Shop | `shop.html` | Full catalog with colour/work/availability filters |
| Collections | `collections.html` | Category cards linking to individual collection pages |
| About | `about-us.html` | Brand story, values, process steps, WhatsApp CTA |
| Shipping | `shipping.html` | Delivery timelines, areas, tracking info |
| Returns | `returns.html` | Returns window, eligibility, exchange process |
| Coming Soon | `coming-soon.html` | Template page for future launches — not linked from nav |

Collection and product detail pages are generated by the build script into `dist/collections/` and `dist/products/`.

## How the build works

Source `*.html` files use markers instead of duplicated markup:

```html
<!--#include header-->
<!--#include footer-->
<!--#include support-widget-->

<!--#products-->              <!-- all products -->
<!--#products limit=6-->      <!-- first N products, sorted by updatedAt descending -->
<!--#collections-->           <!-- collection cards grid -->
<!--#filter-bar-->            <!-- colour/work/availability filter dropdowns -->
```

Running `node scripts/build.js`:
1. Reads `partials/*.html` and `data/products.json`
2. Replaces all markers with generated HTML
3. Appends the current git commit hash to all local CSS/JS URLs for cache busting (e.g. `styles/general.css?v=7c9abf5`)
4. Generates individual PDPs into `dist/products/<slug>.html`
5. Generates category listing pages into `dist/collections/<slug>.html`
6. Writes everything to `dist/` alongside copies of `styles/`, `scripts/`, `images/`, and `fonts/`
7. Regenerates `sitemap.xml` in the root and `dist/` from indexable root HTML pages, products, and collections. Pages marked `noindex` and redirect pages are excluded.

Do not edit `sitemap.xml` manually. Its `lastmod` dates come from Git history for page/template dependencies and product `updatedAt` values, not the build date. Keep `updatedAt` current when changing product content. GitHub Actions fetches full history so these dates remain accurate.

## Build commands

```bash
npm run build     # build only → dist/
npm run preview   # build + serve dist/ locally
npm test          # Node unit tests
npm run test:browser # Playwright desktop/mobile Chromium and Firefox checks
```

Use Node 20 or newer (matching CI). Build and browser runtime code use no npm dependencies. QA uses development dependencies: install them with `npm ci`, then install browser engines with `npx playwright install chromium firefox`. Build before running the browser suite, which serves `dist/` on an isolated local test server and mocks third-party resources.

Run a unit test file with `node --test tests/sitemap.test.js`, or a single case with `node --test --test-name-pattern="discovers new pages" tests/sitemap.test.js`. Run one browser case with `npm run test:browser -- --project=chromium -g "mobile menu"`. On Windows PowerShell, use `npm.cmd` / `npx.cmd` if execution policy blocks the `.ps1` launchers.

Pull requests run unit tests, the build, and browser checks in `.github/workflows/quality.yml`. Deployment runs these same gates before publishing. Require the `site-quality` check in branch protection to prevent merging a failing PR.

The Chromium browser suite includes a three-run, cold-cache mobile loading guard: median LCP <= 2.5 seconds and CLS <= 0.1 under 150 ms latency, 200 KB/s download and 4x CPU throttling. External resources are mocked, so this catches local regressions rather than certifying production Core Web Vitals. Recheck the deployed site with real third-party resources after publishing.

The homepage self-hosts the existing Poppins Latin fonts in `fonts/`, with their OFL licence. Above-the-fold weights are preloaded. `font-display: optional` keeps fallback text stable if a font arrives too late to use on the initial render; other pages retain their existing Google Fonts setup. Do not change this to `swap` without checking delayed-font layout shifts.

The handloom film has a default English caption track at `images/bengal-handloom-saree-weaving.en.vtt`, timed from the supplied transcript. Keep captions synchronized when replacing the video; verify them using the player's caption control.

## Product schema (`data/products.json`)

```json
{
  "id": "JSH-MTK-00000001-RED",
  "parentId": "JSH-MTK-00000001",       // optional — groups colour variants
  "slug": "red-matka-silk-saree-woven-booti-border",
  "name": "Red Matka Silk Saree with Woven Booti Border",
  "category": "Matka Silk",
  "categorySlug": "matka-silk",
  "colour": "Red",
  "work": "Resham Work",
  "availability": "In Stock",
  "isFeatured": true,
  "updatedAt": "2026-09-26T06:00:00Z",  // used to sort featured section — most recent first
  "price": "Price on enquiry",
  "description": "One-line description shown on the card.",
  "fabricDetails": "Detailed fabric description shown on the PDP.",
  "images": ["images/products/jsh-mtk-00000001-red-1.jpg"],
  "whatsappMessage": "Pre-filled text sent when a visitor taps Enquire."
}
```

- New `categorySlug` values automatically get a collection page and filter chip — no other file needs changing
- Products sharing a `parentId` show image swatches linking to each other on their PDPs
- The featured section on the homepage shows the 6 most recently updated products (`updatedAt` descending)

## Draft → Live workflow

Products are authored in `data/all-products.json` (full master catalog) and promoted to `data/products.json` (what the build actually uses) when ready to go live.

To publish a new product:
1. Add the full entry to `all-products.json` with today's date as `updatedAt`
2. Copy the same entry into `products.json`
3. Run `npm run build` and preview
4. Push to `main` to deploy

To feature a product at the top of the homepage, set `updatedAt` to today — the featured section always shows the 6 most recently updated products.

## Brand voice

`brand-context.txt` (committed to the repo) is the source of truth for all copy — brand positioning, product descriptions, what to say and what to avoid. Read it before writing any new page content or product descriptions.

Key rules:
- Bengal-first, not just Bengal — handloom tradition, artisan craft, authentic origin
- No fabricated stats, certifications, or testimonials
- WhatsApp-led commerce — all CTAs lead to WhatsApp enquiry
- Retail and wholesale both welcomed

## URLs

The site uses clean extensionless URLs (`/shop`, `/about-us`, `/collections/matka-silk`). GitHub Pages and the local dev server both resolve these to the matching `.html` file automatically. Do not add `.html` back to internal links in source files or partials.

## Coming Soon page

`coming-soon.html` is a reusable launch template — it is not linked from the nav and has `noindex` set so it won't appear in search. To use it for a new product or collection launch:
1. Update the heading and body copy in `coming-soon.html`
2. Add a link to it from wherever you want to promote it (nav, Instagram bio, WhatsApp)
3. When the launch is live, remove the link and reset the page copy

## Image naming convention

```
jsh-<category-code>-<product-id>-<colour>-<n>.jpg

jsh-mtk-00000001-red-1.jpg     ← Matka Silk, product 1, Red, image 1
jsh-mus-00000001-yellow-1.jpg  ← Muslin, product 1, Yellow, image 1
jsh-cot-00000001-pink-2.jpg    ← Cotton, product 1, Pink, image 2
```

Category codes: `mtk` = Matka Silk, `mus` = Muslin, `mur` = Murshidabad Silk, `cot` = Cotton

## Deployment

Every push to `main` triggers the GitHub Actions workflow (`.github/workflows/deploy.yml`), which runs `npm run build` and deploys `dist/` to GitHub Pages. No separate hosting or database needed.

### Hosting security limitation

GitHub Pages remains the approved host. Repository files cannot configure custom HTTP response headers such as Content-Security-Policy or anti-framing protection (`frame-ancestors` / `X-Frame-Options`). A `_headers` file would not apply, and a CSP meta tag cannot enforce `frame-ancestors`. This limitation is accepted for the current hosting setup; revisit it if moving to a configurable host or proxy. Do not claim these headers are enabled.

### Video audio and captions QA

In Chrome, Edge and Firefox, play the homepage video, unmute its native player, increase player volume, and check Windows Volume Mixer for a muted browser. Verify playback, pause and seek, then listen for narration versus music. Decoder/audio-track checks do not establish audible speaker output. Add caption tracks only from a verified transcript with timings; do not invent dialogue or claim caption compliance from an audio-track check.
